Detection and response that stay on the PC.

deR4Tizer adds EDR-style detection, a 30-day event history and guarded response on top of Microsoft Defender. No cloud, no account, no telemetry. Built for town halls, small businesses and shops that have no SOC and no EDR budget.

01 · Overview

One screen says where things stand

A banner gives the verdict, tiles count what deserves a look, and a list shows what is in order.

  • A collector that stopped is shown as unavailable, never as “nothing suspicious”.
  • It never tells you that you are protected.
  • The Panic button cuts Internet access and states its scope before acting.

02 · Alerts

An alert says what happened and what to do

Each alert names its rule, the MITRE ATT&CK techniques that this rule covers (an attack chain carries those of its own steps) and the reasons behind it, then gives advice in plain words.

  • Only the responses that apply to this alert are offered.
  • Critical alerts go to your IT provider by ntfy, Teams or e-mail.
  • Alerts are grouped into incidents that are never closed automatically.

03 · Connections

See which program talks to whom

Every outbound connection is listed with its program, its signer and its destination, as it happens.

  • Risk is labelled in words, suspicious or threat, with the score kept in the details.
  • “Threat” is reserved for destinations found on a threat list.
  • Block a destination or isolate a program from the same panel.

Coverage

What deR4Tizer watches

The state of each capability, from lab-tested to checked in a VM, is tracked line by line in the capability matrix. None is production-ready yet.

Network

  • Live outbound connections per program, beaconing, a program's first Internet connection
  • Open-source threat lists, refreshed every 12 hours
  • Passive traffic analysis with a live country map, no driver
  • Firewall rule changes and exposure to the Internet

Processes and persistence

  • Process tree with a cumulative score per chain
  • Obfuscated PowerShell, mapped to MITRE ATT&CK techniques
  • Without Sysmon, process creations are read from the Windows audit log (event 4688), so even short-lived programs are seen with their command line
  • Run keys, services, scheduled tasks, WMI and Startup folders: any new or changed entry

Ransomware and data theft

  • Canary files: the program that touches one is suspended
  • Access auditing on sensitive browser and application folders
  • Camera, microphone, remote-control tools and open ports

Events and incidents

  • Mini-SIEM: logons, accounts, processes, services, firewall and alerts, kept 30 days
  • Correlation: brute force, new administrator, cleared log, multi-stage attack
  • Incident tracking with a timeline, closed only by a person and with a reason

Hardening and health

  • A security baseline inspired by Microsoft and Intune, applied through local Group Policy, reversible: reverting restores the original values (checked rule by rule in a test VM)
  • A Defender rule counts as compliant only when Defender actually applies it; side effects (Remote Desktop, UAC prompts, guest shares) are stated before applying, and the full profile leaves Remote Desktop on when it is in use
  • Health page: every collector, alert forwarding and the interface are monitored
  • Syslog (RFC 5424) and a read-only HTTP API for your own SIEM

Experimentalin validation

  • Local NDR: ARP spoofing, rogue DHCP, LLMNR/NBNS/mDNS poisoning · tested in the Kali campaign, except the rogue DHCP server (to be measured again after a fix)
  • IDS / IPS: a subset of the Suricata rule format, IPS off by default · only the built-in test rule exercised in the campaign so far
  • DPI: TLS names, JA3 fingerprints, cleartext HTTP, DNS tunnelling · reopened for work, not yet measured in the campaign

Response

Two things happen on their own. The rest waits for you.

A tool that runs as SYSTEM should not improvise. The response policy sets what may be automatic, and the code enforces it.

Automatic · on by default, can be turned off

Bounded by the policy

Only two actions are taken without anyone asking.

  • Block known-bad addressesAddresses on Spamhaus DROP and Feodo Tracker are blocked at the firewall, at most 30 per hour. Other lists only raise an alert.
  • Suspend what touches a canaryA program that modifies a canary file is suspended. Known, signed software raises an alert instead.
On your click · with confirmation

Decided by a person

Everything else is offered next to the alert and confirmed before it runs.

Block a destinationIsolate from the networkSuspendKill the chainQuarantinePanic: cut Internet
  • The exact command is shown firstPrivileged actions go through an elevated helper that states what it will do before sending it.
Identity is re-checkedThe process is verified again just before each action, to avoid acting on another program that reused the same PID.
Nothing is lifted silentlyA suspension, an isolation or panic mode never ends on its own. At its deadline it is raised again to your IT provider.
Every lasting action is listedThe “Ongoing responses” page shows each one, its deadline and how to undo it.

Under the hood

Two programs, no driver

A Rust service does the watching. A separate interface, without administrator rights, shows what it found.

deR4TizerSvc.exe
Windows service written in Rust, SYSTEM account. Monitoring, response and export.
deR4Tizer.exe
The interface, in English or French, on the .NET Framework that ships with Windows. No administrator rights.
Data folder
Readable by SYSTEM, administrators and the accounts you authorise. Owner and permissions are enforced at every start.
Named pipe
Commands from the interface to the service, accepted from administrators on this computer only.

Trust

Built to stay under control, and honest about its limits

A security tool earns trust by what it refuses to claim. Here is what holds today, and what does not.

Everything local

No account, no cloud, no telemetry. Data leaves only through the alert channels and the SIEM you configure. Threat lists and updates are downloads, nothing is uploaded.

Works offline

Detection, the event history, response and local alerts run disconnected. Useful for isolated environments where a cloud-dependent EDR cannot run.

Defender is never touched

deR4Tizer adds to Microsoft Defender and never weakens or excludes anything. In the test VM, with Defender fully active, the installed product is not detected. That is a signal, not proof on a real machine.

Reversible

Uninstalling removes blocks, firewall rules and canaries, restores the original security settings and deletes the data.

Fails closed

If the ownership check of the data folder fails, settings and secrets are ignored and the interface says so. Updates install only with a matching hash and a pinned signing key.

No black box

Every detection rule has an identifier and a documented entry: rationale, telemetry, expected false positives. Red teams can see exactly what fires, and why.

What it is not

Read this before relying on it.

  • Not an antivirus and not a replacement for Microsoft Defender.
  • Not an enterprise EDR. An attacker with administrator rights can stop the service.
  • Not audited. No independent security review has been done yet.
  • Not signed yet. Windows shows “unknown publisher” until a certificate is obtained.
  • Not proven in the field. It has been tested in a lab and a VM, never on real production machines.
