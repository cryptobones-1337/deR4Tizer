# deR4Tizer capability matrix

State as of 2026-10-24, branch `main` (commit `1cf04fe`, version 4.3), after the merge of PRs #10, #12 to #27, #31 to #37
and #40 to #46; the PRs merged afterwards are described in the rows concerned. No claim here is stronger
than the evidence cited. A PR still open is flagged as such: as long as it is not merged, `main` does not
contain its content.

## States

| State | Meaning |
|---|---|
| planned | Nothing in the code. |
| implemented, not verified | The code exists; no automated test verifies its behaviour. |
| lab-tested | Pure functions or parsers verified by `cargo test --release` (decisions, formats, mini-fuzz); the behaviour on a real Windows is not proven. |
| validated on Windows | Scenarios succeeded with the real service, installed by the MSI, on a disposable Windows runner of the CI (`integration-*` jobs, tables cited). |
| succeeded in Windows Sandbox | Same scenarios, succeeded in a disposable Windows Sandbox (`tests/bac-a-sable`), while GitHub Actions was disabled (from 2026-10-22 to 2026-11-17). Signal, not proof: neither a real computer nor an active Defender. |
| checked (or succeeded) in the test VM | Scenarios or targeted trials succeeded in the Hyper-V test VM (Windows 11, Defender active, without exclusion, reset to its snapshot before and after): `tests/vm/`. Stronger signal than the Windows Sandbox (Defender active, open session), not a real computer; never "validated on Windows (VM)" nor "validated in a VM". |
| production-ready | No capability today. First signed version published: v4.3 (2026-11-23), lot 3d succeeded in a VM on this signed MSI, binaries and MSI signed; but no independent review (the reviews of 2026-11-17 and 2026-11-21 and the audit of 2026-11-23 are done by Claude; deviation decided by the maintainer on 2026-11-23), D4-1 trials not done, trial of the revocation at the expiry of the certificate not done, mandatory CI checks not restored on `main`, nothing verified on a real computer. Open findings of the audit of 2026-11-23: see the rows concerned and `docs/security/threat-model.md`. |

The IDS, the DPI and the NDR are **experimental**, whatever the state of their tests; unfrozen since then (IDS and NDR on 2026-11-16, DPI on 2026-11-18, `CLAUDE.md`, « Unfreezing of the IDS, NDR and DPI » paragraph), they are being validated in the Kali campaign.
