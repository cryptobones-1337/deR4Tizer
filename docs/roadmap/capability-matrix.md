## Scénarios non exécutés (à faire sur une VM)

- Pose des leurres dans le profil d'une session ouverte (3b).
- Restauration avec la session d'un utilisateur standard (3b).
- Lecture des données par un compte standard connecté à la console (3a).
- Refus par `creer_sans_lien` d'une jonction posée entre le contrôle et la création (course).
- Service muet après une mise à jour (3c : simulation seulement).

## Limites ouvertes

- Rien n'est prouvé sur un poste réel avec Microsoft Defender actif : le lot 3d ne tourne que dans la VM de test.
- Export syslog en clair (UDP ou TCP, sans TLS).
- API d'export en clair (HTTP, sans TLS) quand elle écoute sur le réseau local.
- Détection non mesurée sur le terrain : taux de faux positifs non mesurés (les règles ont des tests positifs et négatifs en labo, phase 3).
- Canal de commandes : refus du compte standard, client anonyme, client qui ne lit pas et clients simultanés exercés au scénario 3a ; validation champ par champ de chaque commande testée en labo seulement ; connexion distante (IPC-03) essayée dans la campagne Kali (sixième lot, S-04 : tube distant rejeté, VP en configurations A et C), non consolidée.
- Aucun audit humain indépendant du code n'a été fait.
- GitHub Actions désactivé du 2026-10-22 au 2026-11-17 : les scénarios ont tourné en Windows Sandbox puis dans la VM de test ; la CI est rallumée depuis (3a, 3b et 3c verts au run 44480286774 (PR #205, `cd36ee4`, 2026-11-19)).
